# Fresh LXC memory lab

Fixture-only scripts used for [the .253 validation](../../../../docs/validation/memory-backends-lxc-253-2026-10-08.md). These operate as root in **new disposable Debian 13 guests**. Provisioning creates roles/databases, rewrites guest service definitions and erases synthetic memory authors; do not point them at an existing Aimee or shared PostgreSQL instance.

The source tree is installed at `/opt/aimee`, Go at `/usr/local/go`, scripts at the `/root/aimee-memory-*.{py,sh}` paths used by the launchers. Install `deployed-stack.sh`, `probe.py`, and `extended.py` respectively as `/opt/aimee/scripts/aimee-memory-lxc-stack.sh`, `aimee-memory-lxc-probe.py`, and `aimee-memory-lxc-extended.py`. Build logs use transient systemd units `aimee-memory-bootstrap`, `aimee-memory-build`, and provider setup. `launch.py native|cognee|hillock` launches the compiled stack with first-boot provisioning and enrolled mTLS.

`provision.py` generates mode-0600 credentials; `provider-setup.sh` installs actual pinned providers with guest-private credentials. The Cognee provider uses a deterministic local inference fixture; it validates provider integration, not real model quality. `suites.py` runs native PostgreSQL replay plus selected real-provider contract and C boundaries. `suites-rerun.py` is the explicit second-run path: it rotates disposable test passwords, repairs schema usage and disables JIT for the test administrator. Original logs must be preserved for comparison. It requires databases created by the first run.

`reprobe.py` archives prior shipping evidence before rerun. `extended-launch.py` invokes actual-author erasure, native table-denial, 257-record candidate selection and stale-catalog restoration checks. `extended.py` reuses API helper functions from `probe.py`; all acceptance failures produce a nonzero exit. It stops/restarts only memory children in that guest. Erasure markers must be retained when testing restoration.

To persist an already-running fixture stack, install `resume.py` as `/root/aimee-memory-resume.py`, run `python3 /root/aimee-memory-resume.py capture`, stop the temporary lab service, and enable the supplied `aimee-memory-validation.service`. Capture stores private process environments mode0600, never publish that file. `qualification.py BACKEND service-resume` probes mTLS, listing, KB briefing and post-erasure admission, and snapshots erasure-control hashes. After reboot, `qualification.py BACKEND guest-reboot` verifies availability and retained controls. This resume path reuses provisioned identities and Vaults; it does not recreate first-boot users.

Evidence lives under `/var/lib/aimee-memory-lab`. Publish only credential-free summaries/API fixture outcomes, parsed test statuses and executable/source hashes. Exclude `/root/aimee-validation-env.json`, `resume-private.json`, provider env/token/account files, enrolled certificates, Vaults and entire scratch homes. No script sends Discord messages or changes Discord CT9211.

`focused.py` reuses a running suite's private environment without logging credentials, reruns the recovery deadline case five times and runs the real PostgreSQL evaluation isolation tests. `collect.py BACKEND` produces only publishable fixture evidence and parsed Go test statuses. The private runtime remains excluded. Protect the scratch runtime from age-based `/tmp` cleanup with a guest tmpfiles `x` entry for the exact path in `last-run`, as in this lab.

The `native-fix-*` follow-up scripts repair and validate native's own behavior; native is not subject to the external memory contract. `native-fix-validate.py` requires the existing disposable test databases, rotates only their test credentials and runs targeted/full native regression gates. `native-fix-deploy.py` waits for a passing gate, rebuilds the native stack, installs the actor-erasure function/grants and resumes existing identities. `native-reboot-proof.py before|after` verifies exact corrected fixture content and retained SQL erasure intents across a guest reboot. `native-fix-collect.py` exports only fixture evidence, parsed test statuses and hashes. Never publish the private test environment file. Baseline fixture content includes a run nonce so reruns do not attempt restoration of previously erased payloads.

`external-support-deploy.py` rebuilds only the disposable external guests and retains existing identities/homes. Run `reprobe.py`, then `extended-launch.py`, then `external-support-probe.py` sequentially: the first two intentionally restart memory children and erase fixture authors. `qualification.py` captures service-resume and guest-reboot checks. `transfer-proof.py` checks native record/history → Cognee catalog → Hillock catalog → native, using a disposable cloned schema, including erasure-restoration refusal. Private snapshots/logs must not be published.

Cognee setup now creates a durable service API key and uses `api-key` authentication through Vault. `cognee-service-credential.py` rotates an existing disposable guest's credential explicitly; its overwrite flag is limited to the one-shot Vault helper. Never print or publish the key. The deterministic model fixture remains an integration test, not a quality evaluation. See [current validation](../../../../docs/validation/external-memory-support-2026-10-08.md).
