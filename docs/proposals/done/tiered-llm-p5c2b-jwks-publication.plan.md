> **Archived proposal.** This records the design as it was agreed, not the
> system as it behaves today; parts of it have since diverged. For current
> behaviour see `docs/`, or the code.

- **State:** complete. Implementation, real-PG17/KMS-HWM concurrency and crash recovery, sanitizer/fuzz gates, and adversarial branch review converged with no surviving findings (three review attempts; unavailable seats left the artifacts coverage-degraded).
- **Parent:** `tiered-llm-p5-oidc-control-plane.md`, section 3.
- **Depends on:** P5-C2a's enabled RSA-3072 token root, independent Ed25519 manifest root, canonical JWK codec, and pristine signed publication HWM at value 1.
- **Followed by:** P5-C2c authenticated server-to-kb fetch and durable server cache, P5-C2d token authority, then P5-C3 action composition.

## Boundary

Add an offline, owner-operated publication authority that produces and durably finalizes the first immutable management-token JWKS generation. It must reserve the publication generation with the C2a-bound signed HWM, sign a canonical manifest with the independent custody-backed Ed25519 root, store immutable publication bytes and evidence, and export the exact finalized public artifact after a crash.

This packet has no HTTP route, server cache, token signing, token minting, token-key rotation, overlap/retirement policy, revocation action, listener, management dispatch, or write enablement. The publication HWM 1-to-2 reservation is generation fencing, not token-key rotation. `/v1/management/action` remains unconditional `503`. C2c will expose only finalized bytes over the already-authenticated server-to-kb channel. C2d will be the first online user of the RSA private key.

## Canonical wire contract

Publish one canonical bounded UTF-8 JSON envelope whose exact member order is fixed and whose payload is independently canonical. The payload members are: `format_version` (1), `generation` (1), `valid_from` (integer Unix seconds), `valid_until` (integer Unix seconds), `previous_manifest_sha256` (64 zero hex for the first generation), `keys` (an array containing exactly the canonical six-member C2a RSA JWK), and `jwks_sha256` (lowercase SHA-256 of the canonical `{"keys":[...]}` JWKS bytes). The outer envelope contains `payload`, `manifest_kid`, `signature_alg` (`EdDSA`), `signature` (canonical unpadded base64url of the 64-byte Ed25519 signature over the exact payload bytes), and `manifest_sha256` (lowercase SHA-256 of a length-framed transcript containing the payload, manifest id, algorithm, and raw signature). No component reserializes a parsed object for signature verification.

Times are explicit operator inputs accepted only as canonical decimal integers. Require `valid_from` within a small configured clock-skew bound of the offline process clock, `valid_until > valid_from`, and lifetime within a fixed short maximum used later by C2c. They are persisted at STAGED and never recomputed during resume/export. The artifact contains no host, run id, helper path, custody identity, ciphertext, provider attestation, or mutable endpoint.

Reuse the exported C2a `kb_mgmt_token_jwk`/public-binding implementation rather than introducing a second encoder, and require C2b's fixture to byte-compare its embedded JWK against C2a's frozen JWK fixture. Freeze byte fixtures for the payload, standalone JWKS object, signature transcript, signature, envelope, and every digest. The standalone canonical `{"keys":[...]}` bytes are hashed into `jwks_sha256`; the signed payload embeds the same `keys` array, while the finalized outer envelope is a distinct object. Reject duplicate/unknown members, invalid UTF-8, padding/noncanonical base64url, over-bound arrays/strings, noncanonical RSA encodings, and arithmetic overflow in time validation.

Validity affects consumers, never crash recovery: once staged, an artifact that becomes expired must still converge through CAS_DONE/FINAL without byte changes. Export may reproduce that immutable expired artifact for recovery/audit, while C2c must reject it for authorization and a later lifecycle slice must publish a successor. Tests kill across expiry and prove neither regeneration nor a stranded HWM.

## Publication state machine

Add one platform-scoped publication registry plus immutable generation table and a narrow database adapter. The publisher opens an explicit hardened owner/migration session, verifies exact role/session/search-path/row-security/public-schema state, acquires the global maintenance barrier and one fixed session advisory lock, then holds that same connection and lock across every provider and database operation.

The first publication follows an explicit crash-resumable state machine:

1. `EMPTY`: require both C2a roots exact-final, publication root exact-bound, no candidate/generation rows, vault open, and a fresh verified signed publication HWM of exactly 1. Recover the manifest seed from its fixed v2 custody envelope inside the protected arena, rederive the pinned Ed25519 public key/id, construct and sign the exact generation-1 artifact, then atomically stage its immutable bytes/digests/times/signature and the verified HWM1 evidence. Nothing is fetchable.
2. `STAGED`: re-read the exact staged bytes, validate every database binding and canonical fixture, recover/rederive the manifest key, recompute the signature and complete artifact, freshly verify signed HWM1, then issue the exact provider CAS 1 to 2. A definite compare failure is accepted only when a fresh verified signed read proves exact value 2. Ambiguity, forgery, rollback, outage, changed provider identity, or any other value fails closed without database repair.
3. `CAS_DONE`: record only the exact verified HWM2 attestation against the staged row. A crash after provider CAS but before this commit is recognized from `STAGED` plus a fresh exact HWM2 read. Revalidate the candidate and root bindings, then atomically insert/finalize immutable generation 1, mark the candidate finalized, advance the publication registry to generation 1/HWM2, and append one secret-free WORM publication event.
4. `FINAL`: require exactly one finalized generation/candidate/registry, exact byte/digest/signature/root/HWM bindings, no divergent rows, and a fresh verified signed HWM2. Return converged without mutation and optionally export the byte-identical artifact.

Generation `g` is permanently coupled to the provider transition `g -> g+1`; for this slice only `g=1` is legal. Table constraints hardcode generation 1, and every SECURITY DEFINER stage/record/finalize function independently rejects any generation other than 1 before mutation; a real-PG test calls each with 0 and 2 and proves no rows/audit/provider call. Database staging always precedes the external CAS, and final publication always follows it. No heuristic repair, overwrite, regeneration, resigning, timestamp refresh, or alternate payload is permitted. Thirty-two concurrent identical invocations converge to one candidate/generation/audit use; concurrent different validity inputs conflict without a second provider CAS.

## Custody and secret handling

The dedicated `aimee-kb-jwks-publish` target is the only new binary. Ordinary kb/server/status/provisioner targets link none of its private-custody, database-writer, provider-CAS, or export objects. The publisher may read only the finalized manifest-root v2 envelope and exact public root bindings through narrow owner functions; it never receives or decrypts the RSA token private key.

Recover the 32-byte manifest seed only in an mlocked, nondumpable, wipe-on-fork arena with cancellation disabled across secret ownership. Set `PR_SET_DUMPABLE=0` and `RLIMIT_CORE=0`; reject memory-protection failure; cleanse seed, KEK, DEK, AAD, plaintext, and signature temporaries non-elidably. The KMS helper child receives an allowlisted exact environment, never inherits the database URL or unrelated secrets, and no secret appears in argv, environment, stdout/stderr, logs, audit detail, or errors.

Before decrypt or sign, use a dedicated platform-root adapter with the shipped P7 candidate-to-admit sequence: verify the current signed key HWM, then commit an immutable manifest-root key-use intent and its `vault.key_use` WORM admission before the admitted envelope is returned to the publisher. Bind the admission to manifest root/version, generation, candidate id, payload digest, seal epoch, and purpose; exact replay converges and any mismatch fails before private use. Decryption/signing occurs only from that admitted envelope. A failed admission prevents decrypt/sign. A later signing or finalization failure leaves a truthful admitted-use record, never a falsely successful-publication record. Provider HWM evidence and signature bytes are public but remain bounded and never logged wholesale.

Roundtable seal-recovery ruling: a seal cycle must not strand an immutable STAGED candidate. Key-use identity is also bound to the current seal epoch, so a STAGED resume after unseal appends a new immutable epoch-specific admission for the same manifest root/version/generation/candidate/payload, decrypts only from that newly admitted current-epoch envelope, deterministically re-signs the unchanged payload, and byte-compares the signature before CAS. The candidate's original stage epoch and all artifact bytes remain immutable; no row is restaged or timestamp refreshed. Exact replay within one epoch converges, while different candidate/payload/root bindings conflict. CAS_DONE and FINAL require no private use, accept a later current seal epoch, preserve the original stage epoch only as evidence, and still require fresh signed publication HWM2. Tests cross a seal/unseal between STAGED and CAS, require exactly one admission per used epoch, and prove byte-identical convergence.

## PostgreSQL boundary

Add owner-only tables for a singleton publication registry, immutable candidates, and immutable generations. Bind generation, previous digest, validity, JWKS/payload/envelope bytes and digests, manifest id/public digest, signature, C2a root digests, HWM-before/after attestation digests, seal epoch, candidate id, phase, and creation/finalization times. Constraints and guarded transitions enforce exactly `staged -> cas_done -> final`, generation 1, correct digest lengths, one candidate per generation, one finalized row per generation, and no change to immutable bytes.

Use SECURITY DEFINER functions with definition-time `pg_catalog,pg_temp`, fully-qualified objects, fixed bounded input/output shapes, exact SQLSTATE classes, advisory locking, and transaction-scoped transition permits. Revoke all table/sequence/function access from PUBLIC and explicitly from `aimee_kb_runtime`, `aimee_kb_status_authority`, `aimee_kb_status_provision`, `aimee_kb_token_roots_provision`, migration helper roles, and any later token runtime role; grant the minimal calls only to a new NOLOGIN/NOINHERIT publisher role assumed by the offline binary. Deny owner UPDATE/DELETE/TRUNCATE of finalized generations, registry history, and WORM rows. Add SQLite shape only and no false authority functions. Add the new guarded functions/writers to P7's exact barrier inventory.

The finalized reader prepared for C2c returns one exact opaque artifact and its generation/validity/digests only; in this slice it is owner/publisher-only and is not routed online. It must never expose staged or CAS_DONE bytes. `--export-public` accepts only exact FINAL plus fresh signed HWM2 and emits the stored byte-identical envelope without mutation or audit append.
