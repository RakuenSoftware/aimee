# MR-04 producer and retained-copy inventory

This inventory belongs to the existing Go memory, derived dependency and storage
owners. Current release compares canonical observations even when an asynchronous
consumer is behind. Registry state and queued work are diagnostics, not permission
to release a stale assertion.

| Producer | Retained output and input contract | Invalidation and erasure policy |
|---|---|---|
| Canonical ingestion and conversation extraction | Host-generated creation event, scoped canonical revision; imported provenance remains unverified | One creation family is not an independence certificate; explicit erasure retains independently stored intent |
| Cognification | Memory claims and relations bind producer, owner, exact input/output revisions | Bounded transitive eligibility; generated memories register essential inputs in `derived_memory_registry`; physical subject-erasure closure |
| Cognified rules | `memory-cognify` domain, ownership marker, exact claim revision and output digest | All Go rule views and native consumers use current inputs; global publication requires global ancestors; authored collisions retain their owner |
| Deterministic index | Units, summaries, chunks, episodes, relations, embeddings and profile projections | Producer observations pin actual input revisions; summary policy `summary-input-v1`; source changes suppress serving before asynchronous repair |
| Episode cards | Complete bounded session input set, owner, parent revision and output digest | Current input checks and collection observation; registered essential dependencies; units/copies removed by canonical erasure |
| Session folding | Exact original revisions and content-free archived origin certificates | Original identity remains revocable; checkpoint registered against those revisions; FK payload cleanup; erasure retains original payload digest |
| Feedback extraction and style inference | Versioned directly authored rule observations, rules collection revision and output digest | Changed or missing inputs suppress output; unknown decision provenance cannot automatically become guidance; original authored titles are not adopted |
| Learning observations and reviewed procedures | Existing learning owner publishes canonical revision and supporting memory identity | Memory reads through its declared storage/source contract; review authority remains with learning; source release rechecks canonical inputs |
| Query-derived context | Scoped collection generation, selected versions, temporal deadline and projection commitment, including empty views | New constraints invalidate old query proofs; native refresh replaces prior native proofs once, retains every block in the current build and preserves other retained context proofs |
| Derived dependency registry | Actual producer versions, policy versions, conservative unknown backfill | Existing freshness/rederivation owner follows transitive dependencies; duplicate delivery is idempotent; incomplete ancestry never certifies release |
| Relation/index consumer | Private durable owner identity, snapshot frontier, per-collection applied positions | Restart resumes progress; retention gaps require a new canonical snapshot; current release never waits for this worker to notice revocation |
| Native KB cache | Source/collection release proof and fill generation | Invalidations reject fills begun before invalidation; cached context is revalidated before use |
| Private session stores | Canonical memories/history, prompt context, scratch state, execution state, delegations and session-owned payloads | Atomic erasure captures session/delegation digests; delayed writes refused; startup replays retained intents before either private reader is ready |
| Unowned private agent cache | No reliable input observations in its legacy schema | Erasure clears all entries and future fills become misses; uncached operation remains available |
| Registered application servers | Durable required-owner manifest and authenticated receipt | Offline/revoked owners remain required; only verified removal permits `completed`; count-only legacy coordinators cannot acknowledge |
| User-selected exports and operator snapshots | Detached copies outside live managed-store inventory | Completion explicitly reports `managed_application_stores`; the operator's export/backup retention process owns these copies. Restores must retain control metadata and stop serving until replay succeeds |
| External provider copies | Governed dispatch and payload-free receipt | The application cannot verify external deletion and does not claim that coverage |

Historical records with missing producer observations remain unknown. Backfill
copies deterministic recorded links and versions; it does not infer authorship,
independence, or a new observation from similar text or today's source revision.
Support counts are diagnostics. No support-based ranking or confidence formula
is enabled by MR-04.
