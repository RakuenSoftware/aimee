## The follow-up repairs populated source export

The current `memory_recall_handler` in `src/server/server_api.c` concatenates four recall sections
into primitive records. It neither removes overlapping source identities nor caps the record count.
The new plugin's actual enrolled checks used application baseline `4e822e6ee` with an additional
source-export patch. Its recorded patch deduplicates owner/record pairs, refuses conflicting source
versions/content and bounds the result to 32 records. The patch is absent from the inspected PR head.

The follow-up extracts projection into `src/server/server_native_primitive.c`, deduplicates source
owner/record pairs, validates version and content consistency across the complete view, then caps
output at 32. A conflict in the omitted tail also refuses export. Ordinary recall and authorization
retain their existing paths. The registered native unit target passes overlap, exact large IDs,
owner separation, revision/content conflicts, selection order, the cap and malformed-view cases.
The same test passes AddressSanitizer, UndefinedBehaviorSanitizer and leak checking.

A full local build exposed two mutable argument parsers declaring their working pointers const;
C23 `strchr` preserves that qualifier. Both now retain the mutable argv type while temporarily
splitting key/value arguments, matching the recorded prerequisite patch. Ownership review updates
only the changed API input/generated bytes and the existing server adapter digest. Neither the
allowed symbols nor the ownership rules are expanded. Repeat populated enrolled lifecycle checks
against the final release image before public delivery.
A successful empty-store primitive probe establishes enrollment and transport, but cannot expose
this overlap failure. The [release preparation record](../releases/native-memory-v0.3.2/README.md)
keeps the blocker beside the candidate's execution claims.
